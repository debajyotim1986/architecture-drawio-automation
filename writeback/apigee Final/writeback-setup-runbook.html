Looker write-back to BigQuery · Architecture v5 · One-time set-up

Write-back set-up runbook – every resource, step by step

Everything that must be created before the first write-back click works, in the order to create it: APIs, Workload Identity, service accounts, secrets, BigQuery, network, Entra, ID&A, Apigee, deployments, Looker and monitoring. Each step says who does it, the command or console path, and how to check it worked.

Architecture: Action Hub exchanges an Entra auth token for an ID&A JWT through Apigee → Write-back API verifies the JWT with JWKS → Writer API writes to BigQuery machine-to-machine on service accounts. Write permission = Looker group “Writeback Users” → user attribute writeback_allowed = yes.

Revision 2 – aligned with architecture v6. The Write-back API and Writer API now run on a new, separate GKE cluster in Spoke 2 (not the Looker cluster, not Spoke 1). Added: phase B+ (create the write-back cluster), steps I4, J7 (per-tenant impersonation), K9 (expose the Action Hub to Looker), K10 (egress to Entra), K11 (control-plane access); updated A1, B2, C3, D, E2/E3, K1–K8, O and the summary.

C · Workload Identity and the workload pool

Which “pool” is needed? Google Cloud has two different things called a pool:
  • GKE workload pool – PROJECT_ID.svc.id.goog. Created automatically when Workload Identity is switched on for a cluster; one per project; you cannot name it. This is the one we use: it lets a Kubernetes service account act as a Google service account without key files.
  • IAM Workload Identity Federation pool – gcloud iam workload-identity-pools create. Only needed when an outside identity (for example an Entra token) must call Google APIs. Not needed here: our direction is the opposite – a Google service account signs in to Entra – so the trust is configured on the Entra side as a federated credential (step L2).

C1Switch on Workload Identity on the Spoke 2 cluster (creates its workload pool)

Platform Skip if already enabled.
gcloud container clusters update $LOOKER_CLUSTER --location=$REGION --project=$LOOKER_PRJ \
  --workload-pool=${LOOKER_PRJ}.svc.id.goog

C2Switch the Spoke 2 node pool to the GKE metadata server

Platform Rolls the nodes – plan a window.

C4Check the workload pool and node pools with gcloud

6. The pod can get a Google access token and an ID token

# access token (used by Writer for BigQuery)
kubectl --context=wb-gke exec -n writeback deploy/writer -- curl -s -H "Metadata-Flavor: Google" \
  "http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/token" | head -c 80

# ID token for the Writer audience (used by Write-back API → Writer, step 6)
kubectl --context=wb-gke exec -n writeback deploy/writeback-api -- curl -s -H "Metadata-Flavor: Google" \
