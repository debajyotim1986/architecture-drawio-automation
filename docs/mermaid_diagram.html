1. User journey — what the user does, end to end

A state diagram. Each state is something the user can be in; arrows are the actions that move them between states.

stateDiagram-v2
    [*] --> Writing
    Writing : 1. Writing the Jira story
    Writing --> Normalizing : run normalize_jira_story.py
    Normalizing : 2. Normalizing to surgical format
    Normalizing --> Prompting : open Copilot Chat
    Prompting : 3. Pasting create-diagram prompt
    Prompting --> Reviewing : Copilot finishes MCP calls
    Reviewing : 4. Reviewing the .drawio output
    Reviewing --> Verifying : run verify_mcp.py
    Verifying : 5. Pre-flight verification
    Verifying --> Generating : exit 0
    Verifying --> Prompting : exit 2 (fix and retry)
    Generating : 6. Generating connector-details table
    Generating --> Embedding : table written
    Embedding : 7. Embedding table into .drawio
    Embedding --> [*] : done

3. Create-diagram session — full sequence

One Copilot Chat turn that builds a new diagram from a Jira story.

sequenceDiagram
    participant U as User
    participant CO as Copilot
    participant MC as MCP server
    participant FS as Filesystem

    U->>CO: paste create-diagram prompt
    CO->>FS: read surgical story
    CO->>MC: create_diagram
    MC->>FS: write empty .drawio
    loop 4-6 swimlanes
        CO->>MC: add_container
        MC->>FS: update .drawio
    end
    loop each component
        CO->>MC: add_node (gcp_icon)
        MC->>FS: update .drawio
    end
    loop each connection
        CO->>MC: add_edge
        MC->>FS: update .drawio
    end
    CO->>MC: add_title
    MC->>FS: update .drawio
    U->>FS: run verify_mcp.py
    FS-->>U: exit 0
    U->>FS: run generate_connector_details.py
    FS-->>U: connectors.md ready
    CO->>MC: add_connector_table
    MC->>FS: final .drawio
    CO-->>U: diagram path

4. Update-diagram session — what differs from create

sequenceDiagram
    participant U as User
    participant CO as Copilot
    participant MC as MCP server

    U->>CO: paste update-diagram prompt
    CO->>MC: read_diagram_summary
    MC-->>CO: nodes + edges (compact)
    Note over CO: diff vs. new story
    loop changed nodes
        CO->>MC: update_node
    end
    loop removed elements
        CO->>MC: remove_element
    end
    loop new components
        CO->>MC: add_node
    end
    loop new connections
        CO->>MC: add_edge
    end
    CO-->>U: diff summary

5. MCP request dispatch — JSON-RPC to tool

What server.py does when a single call_tool request arrives over stdio.

flowchart TB
    IN[/stdio JSON-RPC/]
    DEC[Parse request]
    LOOK[Lookup tool in TOOL_REGISTRY]
    VAL[Validate args vs schema]
    CALL[Await handler]
    SER[Serialize result to TextContent]
    OUT[/stdio response/]
    ERR[Wrap error as TextContent]

    IN --> DEC
    DEC --> LOOK
    LOOK --> VAL
    VAL -->|ok| CALL
    VAL -->|bad args| ERR
    CALL -->|ok| SER
    CALL -->|exception| ERR
    SER --> OUT
    ERR --> OUT

6. add_edge pipeline — the five routing passes

When Copilot adds an edge, add_edge.py runs five passes in order before saving. Each pass owns one quality concern.

flowchart LR
    IN[/from, to, label/]
    P0[Append DiagramEdge]
    P1[Fan parallel endpoints]
    P2[Compute waypoints]
    P3[Deconflict lanes]
    P4[Frame busy nodes]
    OUT[/Save .drawio/]

    IN --> P0 --> P1 --> P2 --> P3 --> P4 --> OUT

    classDef io fill:#dae8fc,stroke:#6c8ebf,color:#000
    classDef pass fill:#ffe6cc,stroke:#d79b00,color:#000
    class IN,OUT io
    class P0,P1,P2,P3,P4 pass
#PassConcern
0Append DiagramEdgerecord the edge and auto-assign step number
1_distribute_parallel_endpointssiblings sharing a node fan out across the perimeter
2_compute_waypointscross-container edges route through row-gap "highways"
3_deconflict_highway_lanesedges that share a highway get sub-lane offsets
4_frame_busy_nodesnodes with degree > 3 get a card border

8. Verification flow — what verify_mcp.py checks

Each check is a gate. The first one to fail returns exit 2 with the specific reason.

flowchart TB
    START([verify_mcp.py])
    C1[Tool registry healthy]
    C2[No dangling edges]
    C3[No duplicate labels]
    C4[Every GCP node has icon]
    C5[Every edge renders arrow]
    C6[Parallel edges fanned]
    OK([exit 0])
    BAD([exit 2 with reason])

    START --> C1
    C1 -->|ok| C2
    C2 -->|ok| C3
    C3 -->|ok| C4
    C4 -->|ok| C5
    C5 -->|ok| C6
    C6 -->|ok| OK
    C1 -->|fail| BAD
    C2 -->|fail| BAD
    C3 -->|fail| BAD
    C4 -->|fail| BAD
    C5 -->|fail| BAD
    C6 -->|fail| BAD

9. Connector-table fill flow

generate_connector_details.py has two parallel fill engines plus a hard guard so the table never ships with {TBD}.

flowchart TB
    IN[/diagram + surgical story/]
    SK[Build skeleton table]
    RULE[Run deterministic rule engine]
    KEY{ANTHROPIC_API_KEY set?}
    LLM[Refine with Claude]
    MERGE[Merge rule + LLM]
    GUARD{Any TBD remaining?}
    EXIT0([Write .md, exit 0])
    EXIT2([Emit NEEDS_FILL payload, exit 2])

    IN --> SK
    SK --> RULE
    RULE --> KEY
    KEY -->|yes| LLM
    KEY -->|no| GUARD
    LLM --> MERGE
    MERGE --> GUARD
    GUARD -->|no| EXIT0
    GUARD -->|yes| EXIT2

    classDef step fill:#ffe6cc,stroke:#d79b00,color:#000
    classDef good fill:#d5e8d4,stroke:#82b366,color:#000
    classDef bad fill:#f8cecc,stroke:#b85450,color:#000

    class IN io
    class SK,RULE,LLM,MERGE step

11. Error paths — what goes wrong and where

Common failure modes and how the system surfaces them.

flowchart TB

    F4[Dangling edge]
    F5[Duplicate label]
    F6[Edge missing arrow]

    F5 --> R4
    F6 --> R4
    F7 --> R5[Restart MCP per vscode-restart-formality]
    F8 --> R6[add_connector_table hard guard]

12. Layout constants — single source of truth

These five knobs govern the visual output of every diagram. Edit the source files and run scripts/reroute_diagram.py to retrofit an existing .drawio.

ConstantValueFileEffect
_COLUMN_GAP140add_container.pyHorizontal gap between swimlanes
_CONTAINER_CHILD_STRIDE200add_node.pyVertical distance between stacked icons
_CORRIDOR_INSET70add_edge.pyHalf of _COLUMN_GAP — centres waypoints in the gap
_LANE_BAND_HALF50add_edge.pyMax Y offset for sub-lane deconfliction
_BUSY_DEGREE_THRESHOLD3add_edge.pyNode degree > this triggers the card border
