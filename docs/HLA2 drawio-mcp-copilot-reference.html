01
Stage 01 · Cobalt
Entry & Routing

GitHub Copilot Chat is the only client — there is no custom UI. Every one of the 13 MCP tools is reached from a single typed line, so the router that decides create vs. update is the first thing a new engineer needs to trust.

LOW-LEVEL

.vscode/mcp.json wires Copilot to the server over stdio

  • Transport is MCP · stdio · JSON-RPC
  • Exposes tools/list and tools/call
  • .vscode/settings.json sets useInstructionFiles so repo rules auto-attach
HIGH-LEVEL

One short line routes to create or update

  • Shorthand matched against .github/copilot-instructions.md
  • Runs list_stories / list_diagrams to disambiguate
  • 1 match → use it · 0 → offer create · many → ask
HIGH-LEVEL

The client plane has exactly one member

  • GitHub Copilot Chat drives the whole pipeline
  • No dashboards, no web app — chat is the interface
  • Every downstream tool call originates here
Worked exampleFrom one line to a chosen prompt file

A person types Jira: PROJ-123.txt … create a diagram. Copilot matches the shorthand rule, calls list_stories, finds no existing diagram tied to PROJ-123, and picks prompts/create-diagram.md as the backend prompt to follow for the rest of the run.

02
Stage 02 · Amber
Story Normalization

Business prose is inconsistent; diagrams need a deterministic technical brief. This stage turns a raw Jira note into a canonical document the AI can plan a layout from without guessing.

LOW-LEVEL

normalize_jira_story.py builds the surgical brief

  • CREATE mode vs. diagram-aware UPDATE mode
  • Reads jira-stories/<KEY>.txt + surgical-story-template.txt
  • Writes <KEY>-surgical.txt plus a .bak backup
LOW-LEVEL

The LLM call degrades gracefully

  • Uses Anthropic Claude if ANTHROPIC_API_KEY is set
  • Otherwise verbatim copy, or delegates to Copilot
  • Pipeline stays usable with zero external keys
HIGH-LEVEL

Updates quote the live diagram, not memory

  • UPDATE mode embeds the current diagram summary
  • Node and edge labels are copied verbatim
  • Prevents drift between the story text and the .drawio file
Worked exampleRaw note → surgical brief

A three-paragraph Jira description at jira-stories/PROJ-123.txt is condensed into PROJ-123-surgical.txt — a numbered list of components, their relationships, and the target swimlanes — ready for the planning stage to consume directly.

03
Stage 03 · Crimson
Governance & Guardrails

This is a mandatory pre-build gate — it runs before a single node is drawn, on both create and update paths, and it never guesses on your behalf.

HIGH-LEVEL

One file is the entire source of truth

  • policy/unavailable_services.md
  • Service name + alias ban list
  • Separate 94-row alternate1–4 reference table
LOW-LEVEL

Cascading substitution, never silent failure

  • Alternates ranked by the specific Jira scenario
  • A restricted alternate cascade-skips to the next allowed one
  • The flow always stops and asks
HIGH-LEVEL

The gate is checked at prompt step 2a

  • Applies to every planned component + gcp_icon
  • Mandatory for both create and update runs
  • Presents every option and waits for a human pick
Worked exampleA restricted service, resolved live

Cloud Functions is restricted today. The guardrail offers Cloud Run, App Engine, GKE, and Compute Engine, ranked for the scenario, and the build pauses until a person picks one.

04
Stage 04 · Violet
MCP Core & Tool Layer

The LLM only ever names intent — the server owns every pixel of geometry. Thirteen small, composable tools sit behind a single dispatch registry.

LOW-LEVEL

server.py runs the stdio dispatch loop

  • @list_tools / @call_tool decorators
  • TOOL_REGISTRY: name → (schema, handler)
  • Errors surface as text, not crashes
HIGH-LEVEL

Five tools only read, never mutate

  • list_diagrams · read_diagram
  • read_diagram_summary
  • list_stories · read_story
HIGH-LEVEL

Eight verbs build and edit the diagram

  • create_diagram · add_title
  • add_container (swimlane layers)
  • add_node (gcp_icon, auto-place) · add_edge (fan-out)
  • add_connector_table (zero-TBD) · update_node · remove_element
Worked exampleFour calls build a layered diagram

create_diagram → add_container ×N (one per swimlane) → add_node(gcp_icon=…) for each component → add_edge to connect them. The server resolves layout; the model never specifies coordinates.

05
Stage 05 · Teal
Domain Model & drawio Adapter

An intent-level Pydantic model sits between the tool layer and raw mxGraph XML, so layout stays deterministic instead of depending on manual dragging.

LOW-LEVEL

Diagram / Node / Edge model every intent

  • parser.py ⇄ builder.py round-trip the XML
  • summarize.py strips to id + label only
  • shapes.py holds the style catalog
LOW-LEVEL

Deterministic constants replace manual dragging

  • _COLUMN_GAP = 140px between swimlanes
  • _CONTAINER_CHILD_STRIDE = 200px between stacked icons
  • _BUSY_DEGREE_THRESHOLD = 3 edges → bordered card
HIGH-LEVEL

Service names resolve to real icons automatically

  • gcp_icons.py: name → SVG data URI
  • Curated alias map + snake-case fallback
  • New AI/agent services aliased onto official icons
Worked exampleA node becomes "busy" automatically

When add_edge pushes a node past _BUSY_DEGREE_THRESHOLD (3 edges), the layout engine promotes it from a plain icon into a bordered card — no manual style edit required.

06
Stage 06 · Emerald
Sandboxed Storage

Every store refuses to read or write outside its configured root — path traversal is rejected before a file handle ever opens.

HIGH-LEVEL

Diagrams live under a natural-sorted root

  • diagrams/*.drawio
  • PROJ-2 sorts before PROJ-10 via natural_sort.py
  • Any escaping path is rejected outright
HIGH-LEVEL

Stories are read-only from the server's view

  • jira-stories/* — markdown, JSON, plain text
  • No MCP tool ever mutates a story file
LOW-LEVEL

The icon catalog is a pluggable folder

  • logo_icon_gcp/ today
  • config.py reads env vars for all three roots
Worked exampleA path-escape attempt is stopped cold

A crafted diagram name like ../../etc/passwd is checked against the sandbox root inside diagram_store.py and rejected before any read or write is attempted.

07
Stage 07 · Cyan
Verification & Delivery

Nothing ships until an automated gate proves the diagram is structurally sound — this is the last checkpoint before hand-off.

HIGH-LEVEL

Exit 2 means the diagram does not ship

  • verify_mcp.py — the hard gate
  • Checks registry, dangling edges, icons, arrowheads, fan-out
  • Exit 0 = ship-ready
LOW-LEVEL

The connector table is rule-first, LLM-second

  • generate_connector_details.py — 14 columns
  • Optional Claude refine pass
  • Zero-TBD guard refuses to embed an unfilled cell
LOW-LEVEL

Two tests anchor the riskiest logic

  • test_natural_sort.py — version ordering
  • test_parser.py — full drawio round-trip
Worked exampleA gate failure loops the build back

verify_mcp.py finds one dangling edge and exits 2. The create-diagram prompt catches this and loops back to repair the edge before ever offering the finished file.

Stage 08 · Indigo
Docs, Templates & Cross-OS Tooling

Every operating system gets the same six commands, and every document has exactly one reason to exist.

HIGH-LEVEL

Two markdown files run the whole pipeline

  • create-diagram.md — 12-step flow, step 2a guardrail
  • update-diagram.md — incremental variant
  • prompt.md — a recipe cookbook
HIGH-LEVEL

high_level_instruction.md is the map of the maps

  • README.md — pitch + quickstart
  • architecture.md (prose) vs. component_details.md (table)
  • vscode-restart-formality.md — mandatory checklist
LOW-LEVEL

18 scripts, one command, three shells

  • linux/*.sh · mac/*.sh · windows/*.ps1
  • setup · run-server · normalize · verify · demo · clean
Worked exampleOne file, two representations

component_details.md is the tabular source of truth this reference page's content was assembled from — component.md tells the same story in prose for a first read-through.

Micro-Glossary

Jargon and acronyms used throughout this map, defined once.

MCP
Model Context Protocol — the stdio/JSON-RPC contract Copilot uses to call server tools.
mxGraph XML
The XML dialect draw.io / diagrams.net files are written in.
Pydantic model
Python data-validation classes used for the Diagram / Node / Edge intent model.
Swimlane
A vertical container grouping nodes that belong to the same layer or actor.
Fan-out
Edge routing that spreads multiple connections leaving one node to avoid overlap.
Busy node
A node whose edge count crosses a threshold and gets promoted to a bordered card.
Zero-TBD guard
A rule that refuses to embed a table if any cell is left unfilled.
Natural sort
Digit-aware ordering so PROJ-2 sorts before PROJ-10.
Sandbox
A store that rejects any file path resolving outside its configured root.
Guardrail
A mandatory pre-build check — here, the restricted-service policy gate.
TOOL_REGISTRY
The name → (schema, handler) map the server dispatches every tool call through.
gcp_icon
The parameter that resolves a service name to its official icon SVG.

Suggested Study Path

  1. Read high_level_instruction.md and architecture.md for the map of the maps.
  2. Trace one prompt end-to-end through prompts/create-diagram.md.
  3. Read server.py and the tools/__init__ registry to see dispatch in action.
  4. Study the Diagram / Node / Edge Pydantic model in drawio/parser.py and builder.py.
  5. Read policy/unavailable_services.md and follow the guardrail through step 2a.
  6. Run verify_mcp.py against a sample diagram and intentionally break something to see it fail.
  7. Run the OS wrapper scripts locally: setup → run-server → normalize → demo.
  8. Modify one tool (e.g. add_node) and add a pytest before shipping the change.
